# ПЛАН: улучшение распознавания в Scribe без потери лёгкости

> Статус: черновик для обсуждения. Код не меняем, пока не будем на 100% уверены в пути.
> Дата: 2026-10-02

## 1. Цель

Убрать главные боли Vosk-small, не сломав то, за что любят Scribe:

1. Окончания путаются, точность низкая.
2. Нет пунктуации и заглавных букв из модели. Сейчас только костыль `replaces`: "запятая/точка/новая строка".
3. Хочется как в Gboard на Android: говоришь — текст сразу печатается, знаки и заглавные появляются сами, работает оффлайн.

## 2. Ограничения и баланс (уточнено)

1. **Ориентир, а не догма: ~1-3% CPU на Ryzen 5 5600, работает даже на 1 vCPU.** Это идеал текущей версии, его хочется сохранить для базового сценария, но не ценой запрета тяжёлых моделей. У кого-то слабее, у кого-то 12-16 ядер — им можно больше.
2. **Мультидвижок = раздувание exe и нагрузки, если тащить всё в базу.** Поэтому база остаётся лёгкой, а Whisper / Parakeet / Moonshine / FunASR / Silero / Coqui — только как опциональные плагины.
3. **Размер exe не раздувать в базе.** Сейчас `scribe.spec` — `onefile + upx`, внутри `vosk` (~50-100 МБ). CUDA в базовый комплект не кладём: это +2-4 ГБ. GPU (CUDA/Vulkan/DirectML) — только если уже стоит у пользователя, с fallback на CPU.
4. **Модели и тяжёлые зависимости качаются отдельно, а не лежат в exe.** Как сейчас через `ModelManager` + on-demand pip/onnx. Не поставил движок — не платишь ни мегабайтом, ни процентом CPU.
5. **Мультиязычность.** Пунктуация нужна для любого языка, который скачал пользователь, а не только для русского.
6. **Оффлайн и приватность сохраняем для всех движков.**

Баланс такой: `лёгкое ядро по умолчанию (Vosk-small / sherpa-small, 1-3% CPU) + тяжёлые движки как включаемые модули для мощных ПК`. Палка о двух концах решается не выбором одного, а архитектурой "ядро + плагины".

Вывод: по умолчанию остаёмся на лёгком CPU-стриминге. Всё тяжёлое — плагином/переключателем.

## 3. Почему Vosk-small так себя ведёт (фундамент, не баг)

* `vosk-model-small-ru-0.22 (45М)`: WER ~22-32% по данным Alpha Cephei. Архитектура Kaldi TDNN + n-граммный LM, словарь в нижнем регистре без знаков. Она физически не может выдать `,.?!` и заглавные.
* Пунктуация требует конца фразы. Поэтому стриминг всегда сырой, красота возможна только на `final` после паузы.
* Whisper даёт пунктуацию из коробки, но это батч-модель: чанки 1-3 сек + декодирование целиком = задержка 1-2 сек + 100% ядра CPU. Эксперимент `VoiceTyper-Whispper (faster-whisper large-v3)` это подтвердил: ноут гудит.

Отсюда архитектура, к которой пришли все аналоги (VocOnly, OpenWhispr, VocaLinux, WhisPaste):
`быстрый стриминг для глаз (сырой partial) -> пауза VAD 0.7-1с -> один умный проход только по финальной фразе -> замена хвоста diff-ом`.

В Scribe хук для этого уже есть: `_apply_partial()` vs `_apply_final()` в `scribe/vosk_recognizer.py`.

## 5. Этапы работ

### Этап 0. Замер базы (сделано частично 2026-10-02, есть блокер)
* Vosk-small-ru-0.22 локально: 30с аудио чанками как в приложении → `wall 1.83с, RTF 0.061` (в 16 раз быстрее realtime). Подтверждено: базовый режим почти ничего не стоит.
* Sherpa по официальным данным авторов (C++ `sherpa-onnx`, 1 поток CPU): `RTF 0.04 (bn zipformer2) / 0.10 (korean int8) / 0.15 (zh int8)`. Тот же порядок что Vosk, чуть тяжелее.
* Режим "слушать постоянно" (auto_stop_timeout=0) сохраняем, push-to-talk не навязываем.
* ⚠️ БЛОКЕР (разрешён 2026-10-03): `OnlineRecognizer` (стриминг) на этом ПК не вис, а молча убивал процесс через `_Exit(-1)` — выяснилось замером exit-кода. Причина: несоответствие модель/API. `sherpa-onnx-zipformer-ru-2025-04-20` — это NON-streaming модель (так и написано в её метаданных), `small-zipformer-ru-2024-09-18` и NeMo-transducer не содержат нужных метаданных для streaming-инициализации. Вывод: наш загрузчик обязан проверять метаданные ONNX ДО создания recognizer, иначе упадёт всё приложение. Проверено чтением метаданных через `onnx` напрямую.
* ✅ Рабочий путь: `OfflineRecognizer.from_nemo_ctc` (`sherpa-onnx-nemo-ctc-giga-am-v2-russian-2025-04-19`, 167МБ): загрузка 1.2с, 11.3с аудио за 1.39с (**RTF 0.123**, ~8x realtime на CPU), текст безупречный (`...украдкой на песни грешные мои у лукоморья дуб зеленый`). Lowercase без знаков — их ставит наш пунктуатор. Архитектура: Vosk partials (живо) + NeMo CTC по VAD-чанкам (точно) + rubert punct + caps. Стриминговый RU-transducer в релизе sherpa отсутствует — не ищем, идём двухпроходной схемой.
* Окружение после замеров почищено (sherpa/onnxruntime/psutil удалены из venv, остался только vosk 0.3.45).

### Этап 1. Мультидвижок как "ядро + плагины" (без слома)
* Не сносить Vosk. Ядро остаётся лёгким: `Vosk-small / sherpa-small streaming`.
* Новый код: общий интерфейс `BaseRecognizer` (сигналы `rms/state/text_recognized`, методы `start/stop/set_mode/set_device/set_inserter_type`, `partial_prev + _apply_diff`). `scribe/sherpa_recognizer.py` — первый плагин. Дальше так же втыкаются `whisper_engine.py, parakeet_engine.py` и т.д.
* `voice_typer_controller.py + controller_loader.py`: фабрика `engine: vosk | sherpa-stream | whisper-file | parakeet | ...`. Не выбран — не грузится, не занимает RAM/CPU.
* Зависимости плагинов не в базовом `requirements.txt / scribe.spec`, а `requirements-whisper.txt, requirements-parakeet.txt` + докачка по кнопке в UI. Кто на слабом ПК — просто их не ставит, exe остаётся ~100МБ.
* GPU: в базе только CPU ONNX. CUDA/Vulkan/DirectML — детект "есть у пользователя — используем, нет — CPU fallback", ничего не тащим в дистрибутив.

### Этап 2. Трёхуровневая пунктуация (только на final, partial не трогаем)
* Уровень 1 (делаем): голосовые команды + правила. Расширить `replaces.{lang}`: `ru: точка/запятая/восклицательный/вопросительный/двоеточие/тире/новый абзац`, `en: period/comma/exclamation/...` и т.д. + "после `. ! ?` — заглавная" + per-language типографика («ёлочки» vs "лапки").
* Уровень 2 (делаем): tiny нейро-пунктуатор на final. Один мультиязычный, ONNX int8, 30-100МБ, 50-150мс на фразу, запуск только по VAD-паузе. Если стриминг-модель уже с ITN — скипаем.
* Уровень 3 (пока НЕ делаем, только место): LLM-полировка опционально (Ollama локально: убрать "эээ", деловой стиль, перевод). Тумблер `выкл` по умолчанию.
* Приёмка: на слабом CPU уровень 2 выключается одной галочкой, всё возвращается к уровню 1.

### Этап 3. UX-мелочи из чужих приложений (после 1-2)
* Из VocOnly/OpenWhispr: `удерживай-говори-отпустил = красиво`, двойное нажатие = сырое без AI; `committed+tentative` отображение.
* Из whisper-local/WhisPaste: `pre-roll 500мс + warmup модели` (не режет первое слово), `silence trimming`, Voice Snippets.
* Из VocaLinux: автосовет движка под железо.
* Из vosk-cli-dictation: `config.yaml` с типографикой на язык.

## 6. Что НЕ делаем

* Не кладём CUDA в exe.
* Не ставим тяжёлую модель по умолчанию.
* Не гоняем пунктуатор на каждый partial.
* Не делаем отдельный пунктуатор на каждый из 32 языков: нейронные модели только там где есть готовые (ru, en), остальным — универсальные правила.
* Не переписываем `inserters/, replacements.py, hotkeys` без нужды — они уже хорошие.

## 8. Пунктуатор поверх Vosk (реализовано 2026-10-03, прототип)

Что сделано (код уже в репо, Vosk и UX не тронуты):
* `scribe/punctuator.py` — пайплайн только на final: нейро-пунктуация (ONNX int8) → чистка дублей → заглавные начал предложений (состояние между финалами) → заглавные имён через pymorphy2. Все тяжёлые зависимости опциональны, без них — тихий fallback на правила.
* Интеграция в `VoskRecognizer._apply_final` до голосовых замен; файл и колбэк тоже получают красивый текст. Тумблер `enable_punctuation` в settings, прогрев модели/словарей в фоне.
* Модель: `markusiko/rubert-base-punctuation` → свой экспорт в `models/punct/ru/{model.int8.onnx 174МБ, tokenizer.json}` (gitignored). Рантайм: `onnxruntime + tokenizers + pymorphy2` (в exe пока не кладём — плагины).
* Имена без LLM: Natasha NER на нижнем регистре слепая, вместо неё pymorphy2 (`Name/Surn/Patr/Geox`, порог 0.5) + правила `санкт петербург`, `прилагательное + гео (нижний новгород)`. Двусмысленные (`надежда/вера`) остаются строчными — решит личный словарь позже.

Замеры (Ryzen, CPU): нейро-проход int8 ~7мс/фразу, e2e финал ~9-12мс, первая фраза ~0.7с (фоновая загрузка). Примеры: `привет как дела что нового → Привет, как дела, что нового?`, `иван петров приехал из санкт петербурга → Иван Петров приехал из Санкт Петербурга.`
* ⚠️ Грабли: на Windows `onnxruntime` надо импортить ДО PyQt5 (иначе DLL-конфликт) — сделано в `run.py`.
* Фикс 2026-10-02 (по живому тесту): заглавные теперь ставятся и ПОСЛЕ голосовых замен (`capitalize_actions` + `strip_punct_around_breaks`): сказанное "точка" даёт ".", следующее слово — с заглавной; `,.` от связки "нейро-запятая + точка" чистится в "."; сиротские знаки вокруг `[Enter]` вырезаются. Проверено: `я иду домой точка завтра будет дождь → Я иду домой. Завтра будет дождь`, `привет новая строка как дела → Привет,\n Как дела?`.
* Фикс 2026-10-02 (критический, найден пользователем): флаг `next_sentence_start` был инвертирован — после `. ! ?` возвращал False, новые предложения оставались строчными. Теперь True. Проверено связкой финалов: `сегодня было солнечно → Сегодня было солнечно.` + `завтра обещают дожди → Завтра обещают дожди.` + `меня зовут маша я живу в кишиневе → Меня зовут Маша. Я живу в Кишиневе.`
* Правило запятой (2026-10-03, по живому тесту): после запятой всегда строчная, кроме имён (ru — pymorphy-исключение, uk — частично). Работает и внутри фрагмента, и на стыках через carry-флаг; для en не применяется (там у модели свои +Upper). Украинский: только правила (нейромодели нет), заглавные начал предложений + запятые; ук. словари pymorphy имён не метят — вокативы вроде «Марічко» пока limitation под будущий личный словарь.
* Английский (2026-10-03): `felflare/bert-restore-punctuation` → свой экспорт `models/punct/en/{model.int8.onnx 107МБ, tokenizer.json}`. Стиль меток `this_word_case` (`OU/.U/?O...`: знак после слова + регистр этого слова — имена и места из модели). pymorphy только для ru. Проверено: `my name is john smith and i live in london → My name is John Smith and I live in London.`
* Переключение RU на small (2026-10-03): готовая `ekhodzitsky/rupunct-small-onnx` (MIT, 29МБ) лучше нашего экспорта markusiko (174МБ): тот же уровень, 0.7мс/фразу, регистр из коробки (33 метки UPPER/LOWER/TOTAL + знак). Живой тест пользователя: small ставит точки лучше — markusiko сильно дробил предложения. Пунктуатор расширен: стиль `this_word_case_total`, входы по факту сессии (token_type_ids), пробелы вокруг тире.
* Индонезийский: готовой punct-модели не найдено — только правила.
* NeMo-двухпроходка: исследована и ОТКЛОНЕНА (2026-10-03). Причины: пользователь сидит на big-0.42, выигрыш ~нулевой местами хуже (термины), +сложность и баги. Код прототипа (`rescorer.py`) удалён из репозитория, цифры сравнения сохранены выше. Тумблер `enable_rescore` тоже убран.
